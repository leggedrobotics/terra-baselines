# Pull cone, turn-keeping moves and native dump observation

Branch `pull-cone-trap-dumpobs` in
`.worktrees/terra_pull_cone_20261008/{terra,terra-baselines}`. Its first commit
in each repository is the exact, previously uncommitted source of the
scratch-teacher campaign (CSCS 4994593 / 5000386). The changes follow on top.
Design and semantics: Terra `docs/PULL_DIRECTION_ALIGNMENT.md`, section
"October 8 options".

## Why

The 8 Oct finishing diagnosis found 0/40 completions with the 2.5 m radial pull
rule. A native oracle dig-order planner showed the maps were finishable, but
three env properties made the task far harder than intended:

- The pull had to be exactly radial, which was not the intended rule; the
  intent was any direction within the +-30 degree cabin sector. With 4.0-6.5 m
  reach, a radial pull needs the target to cover the whole reach segment.
- 5-tile tracked moves could shuttle the machine between two stops where it
  cannot turn (17413: only 2 reachable poses).
- `local_map_dumpability` counted dumpable cells to 6.5 m in the dig cone,
  while native dumping reaches 6.0 m and has further vetoes. In replay states it
  showed dump room where DO did nothing at 102 headings.

## Settings

| TrainConfig / CLI | Terra field | Value in `gru_generalist_512_pull_cone` |
| --- | --- | --- |
| `--pull_half_angle_rad` | `EnvConfig.pull_half_angle_rad` | 0.523598776 (30 degrees) |
| `--tracked_move_keeps_turn` | `EnvConfig.tracked_move_keeps_turn` | true |
| `--native_dump_observation` | `EnvConfig.native_dump_observation` | true |

`gru_generalist_512_pull_cone_mixed` adds half precision lanes, as in
`_pull_direction_mixed`. The trainer and evaluation entry points build
`TerraEnvBatch` with matching static switches. Terra refuses a lane config that
enables a rule the batch was not built with. `native_dump_observation` changes a
policy input, so it is refused together with a frozen teacher checkpoint.
Policy input shapes are unchanged.

## Evidence

Native oracle dig order on the 8 Oct training panel, with the cone and
turn-keeping moves. Every action runs through native transitions:

| Map | Radial rule (best of 5 heuristics) | Cone + turn-keeping |
| --- | --- | --- |
| 15360 T trench | finished, 377 actions | finished, 307 |
| 10752 road trench | 128/139 at 701 | finished, 389 |
| 17413 rectangle, precision | 569/570 at 623 | finished, 447 |
| 17411 rectangle, bulk | finished, 702 | finished, 457 |
| 17411 rectangle, precision | 477/480 at 434 | finished, 522 |
| 13824 straight trench | 88/90 | 83/90 (planner stops: no legal dump among its candidate cuts) |
| 17413 rectangle, bulk | 541/570 | 416/570 (greedy took 5 unsafe cuts) |

The greedy planner is a finishability witness, not an optimum, and a failure is
not an impossibility proof. Median legal base positions per trench cell rise
from 37-46 (radial) to 131-144 (cone), against 229-260 under the old rules.

Native dump observation sign versus native loaded DO: 2880/2880 agree
(2 policies x 40 lanes x 3 saved states x 12 headings).

Step cost:

| Variant | ms per 512-lane env step (RTX 4090) |
| --- | ---: |
| Campaign source | 17.9 |
| This branch, options off | 17.9 |
| This branch, all three on | 38.1 |

The times cover the native step and the observation wrapper, with per-lane
config as in training and static switches set as TerraEnv sets them. They
exclude the PPO update. A run under load that timed each option separately
attributed almost all of the increase to the cone (+13 ms), with turn-keeping
and the dump observation within noise. The cone is evaluated about 5 times per
step (DO, the observation channels, the trench-alignment observation), so
sharing one evaluation is the next optimization if needed.
